# 論文想法資料庫維護指南 (Maintenance Guide)

這份文件記錄了未來應該如何新增、更新或維護你的「論文想法資料庫 (Thesis Idea Database)」。

## 💡 為什麼要建立這個資料庫？（架構設計理念）
寫論文是一個長期且充滿碎片化靈感的過程。透過這個 Skill 建立的想法資料庫，有以下好處：
1. **保留真實語氣**：將你的核心觀點（極高權重）與 AI 的客觀分析（輔助權重）分離記錄，確保未來 Agent 在幫你潤稿時，不會失去你真實的聲音與理解。
2. **脈絡連貫性**：隨著靈感累積，Agent 可以在每次新增內容時，幫你 Review 並關聯先前的想法，將碎片化的點子串接成連貫的論文結構。

---

## 📝 如何新增或更新一個想法 (Idea)？

當你有新的想法時，可以直接呼叫 Agent 幫你加入此資料庫。

### 推薦的 Prompt 範本：

> 「我有一個新的論文想法要加入 **thesis-idea-database**。
> 
> **我的想法是：**
> [填入你親自打的文字，越真實、口語越好，這是你的核心論點]
> 
> **AI 過去的參考資料是：**
> [填入 AI 的回應、文獻整理或實驗數據結論]
> 
> 請幫我建立一個新的 idea markdown，並先 Review 現有的 `ideas/` 目錄。幫我在新檔案中建立雙向連結或邏輯關聯，並簡短報告這個想法在整篇論文中的定位。」

---

## 🤖 給 Agent 的更新流程 (Agent Workflow)

當 Agent 收到新增或更新想法的請求時，**必須嚴格遵循以下步驟**：

1. **檢索現有資料**：先使用 `list_dir` 和 `view_file` 讀取 `ideas/` 目錄下的現有內容，理解目前的論文脈絡。
2. **建立檔案**：在 `ideas/` 目錄下創建有意義命名的小寫英文 `.md` 檔案（例如 `002_mac_scheduler_impact.md`）。
3. **結構化內容**：依據以下格式寫入文件：
   - 標題與建立時間
   - 預估的論文章節位置
   - 🗣️ 使用者真實想法 (User's Core Thought) - *標示：極高權重*
   - 🤖 AI 佐證與研究 (Agent's Supporting Evidence) - *標示：參考權重*
   - 🔗 關聯性 (Related Ideas)
4. **建立邏輯關聯 (Review & Link)**：在「關聯性」區塊中，明確寫出此想法與哪些舊 Idea 有關，是「延伸」、「對比」還是「前置條件」？如果必要，一併更新舊的 Idea 檔案加上雙向連結。
5. **進度報告**：向使用者簡短總結已建立的關聯，以及這個想法如何讓整篇論文更有說服力。

## 目錄狀態
現有的想法存放於 `ideas/` 目錄中。使用者隨時可以對 Agent 說：*「幫我回顧一下目前的 idea 資料庫，有沒有哪些邏輯斷層需要補充實驗？」* 讓 Agent 化身你的學術討論夥伴。
