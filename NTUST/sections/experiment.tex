\chapter{Experimental Results}
\label{sec:experiment}

\textcolor{blue}{Experiments were conducted to verify the proposed delay management method within an OpenAirInterface (OAI) nFAPI End-to-End environment. To ensure the statistical reliability of the evaluations, each reported throughput value represents the average of 180 data points (3 independent trials $\times$ 60 samples per trial).}

\textcolor{blue}{To validate the hypothesis and the effectiveness of the proposed dynamic trigger scheduler algorithm, the experimental scenarios are structured as follows: Section~\ref{subsec:experimental_scenario} outlines the software, hardware environment, and the automated evaluation framework. Section~\ref{subsec:scenario_1} validates the Exponentially Weighted Moving Average (EWMA) mechanism for the PNF arrival offset ($\Delta t_{arrive}$). Section~\ref{subsec:scenario_2} benchmarks the performance in terms of peak throughput and MAC Round-Trip Time (RTT) against static baselines. Section~\ref{subsec:scenario_3} evaluates the stability of the proposed method under varying levels of network congestion.}

\textcolor{blue}{To ensure automated measurement and analysis with consistent data quality, an automated evaluation rApp was developed to operate on the Non-Real-Time RAN Intelligent Controller (Non-RT RIC) within the O-RAN Service Management and Orchestration (SMO) framework \cite{oran_architecture}, as illustrated in Figure~\ref{fig:rapp_architecture}. This rApp automates the start-up of both the VNF and PNF. Once the gNB is successfully established, the rApp automatically connects to the control PC via SSH to toggle the UE's airplane mode using Android Debug Bridge (ADB), and subsequently uses SSH to launch the iPerf server on the CN server. It then executes a series of pre-scheduled iPerf test cases automatically. Finally, the rApp collects all log files via O1 SFTP and utilizes Python scripts to automatically plot the subsequent data analysis charts. A key capability of this framework is the automated configuration of network latency simulation via Linux Traffic Control (TC) at both the MAC feedback link ($T_5-T_4$) and the fronthaul segment ($T_2-T_1$), which is essential to validate the split-architecture stability under non-deterministic latency.}

\section{Scenario I: Validation of EWMA for PNF Arrival Offset ($\Delta t_{arrive}$)}
\label{subsec:scenario_1}

\textcolor{blue}{This scenario validates the effectiveness of applying an Exponentially Weighted Moving Average (EWMA) to smooth the PNF arrival offset ($\Delta t_{arrive}$). The raw timing offset received from the PNF can exhibit high variance due to network jitter and processing delays. Figure~\ref{fig:exp1} illustrates the impact of EWMA processing. Without EWMA (Figure~\ref{fig:exp1a}), the arrival offset fluctuates significantly, which could lead to unstable scheduling decisions. By applying EWMA (Figure~\ref{fig:exp1b}), the high-frequency jitter is effectively filtered out, providing a stable baseline for the timing adjustment algorithm.}

\section{Scenario III: Stability under Network Congestion}
\label{subsec:scenario_3}

\textcolor{blue}{To test the robustness of the system, we injected artificial network congestion using Linux TC, varying the one-way delay (OWD) and jitter at the $T_2-T_1$ and $T_5-T_4$ segments. As depicted in Figure~\ref{fig:exp3}, while the static configuration experienced catastrophic throughput drops and frequent connection resets when latency exceeded the fixed window, the proposed adaptive timing control dynamically expanded the slot-ahead ($S_{ahead}$). This expansion allowed the MAC scheduler to pre-trigger messages, ensuring they arrived at the PNF within the valid window despite the increased transport delay. Consequently, the system maintained stable throughput even under congestion levels that previously caused complete synchronization failure.}
