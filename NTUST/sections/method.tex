\chapter{Proposed Method}
\label{sec:method}

This chapter details the proposed dynamic timing adjustment framework. To address the unstable transmission latency during packet transmission between the PNF and VNF, we propose two core timing control algorithms: node sync for software-level clock synchronization and delay management for slot-level adaptive delay management. The timing control of this system is organized as a closed-loop system, ensuring that the VNF-side scheduling can dynamically track and compensate for both microsecond-level clock drift and slot-level transport latency variation. The two core algorithms cooperate as follows:

\begin{enumerate}
    \item \textbf{Node sync:} Maintains phase and slot boundary alignment between the VNF and PNF. It periodically exchanges timestamps to calculate the absolute phase offset, correcting for hardware clock drift (Clock Drift).
    \item \textbf{Delay Management:} Tracks and estimates packet transport delays and jitter at the slot level, dynamically adjusting the slots ahead ($S_{\mathrm{ahead}}$) to guarantee that control messages fall within the PNF's strict timing window.
\end{enumerate}

\section{Node sync}
\label{subsec:node_sync}
To achieve software-level clock synchronization, the system implements a latency probe procedure compliant with the nFAPI specification. In this procedure, the VNF periodically transmits a downlink node synchronization (DL Node Sync) message containing a parameter $t_1$, which represents the transmission time offset in microseconds relative to the VNF SFN/slot 0/0 time reference. Upon receiving this message at the transport layer, the PNF records $t_2$, representing the arrival time offset in microseconds relative to the PNF SFN/slot 0/0 time reference. The PNF then immediately responds by sending an uplink node synchronization (UL Node Sync) message back to the VNF, indicating the echoed $t_1$, the recorded arrival offset $t_2$, and a parameter $t_3$ representing the transmission offset of the uplink message relative to the PNF SFN/slot 0/0 time reference. When the VNF receives the UL Node Sync message, it records a local arrival timestamp $t_4$, representing the arrival time offset in microseconds relative to the VNF SFN/slot 0/0 time reference.

Because the nFAPI timestamps are constrained by a 1024 subframe number (SFN) loop, all offsets wrap around every $10.24$~seconds ($10240000$~\textmu s). The algorithm calculates the differences $d_1 = t_2 - t_1$ and $d_2 = t_4 - t_3$, applying a wrap-around correction to align them within the interval $[-5120000, 5120000]$~\textmu s. The VNF then calculates the instantaneous clock offset between their respective time references:
\begin{equation}
\mathit{offset} = \frac{d_1 - d_2}{2}
\end{equation}
To prevent timing adjustments from causing control loop oscillations, the synchronization control loop implements a state-based locking mechanism. The system has two synchronization states: locked ($\mathit{sync\_locked} = 1$) and unlocked ($\mathit{sync\_locked} = 0$). In the locked state, the VNF monitors the drift of the local clock. If the absolute offset exceeds the slot duration $T_{\mathrm{slot}}$:
\begin{equation}
|\mathit{offset}| > T_{\mathrm{slot}}
\end{equation}
the VNF unlocks the synchronization ($\mathit{sync\_locked} = 0$) to trigger re-synchronization. In the unlocked state, the VNF checks whether the offset has converged within the slot duration $T_{\mathrm{slot}}$. If $|\mathit{offset}| \le T_{\mathrm{slot}}$, the system locks the synchronization state ($\mathit{sync\_locked} = 1$). Otherwise, the VNF decomposes the offset into a slot-level adjustment $S_{\mathrm{adj}}$ and a microsecond-level adjustment $\mu s_{\mathrm{adj}}$ based on the slot duration $T_{\mathrm{slot}}$:
\begin{equation}
S_{\mathrm{adj}} = \mathit{offset} / T_{\mathrm{slot}}
\end{equation}
\begin{equation}
\mu s_{\mathrm{adj}} = \mathit{offset} \pmod{T_{\mathrm{slot}}}
\end{equation}
These adjustments are accumulated into the global adjustment variables:
\begin{equation}
\mathit{slot\_adjustment} \gets \mathit{slot\_adjustment} + S_{\mathrm{adj}}
\end{equation}
\begin{equation}
\mathit{us\_adjustment} \gets \mathit{us\_adjustment} - \mu s_{\mathrm{adj}}
\end{equation}
The negative sign in the microsecond adjustment reduces the local thread sleep time when the VNF clock is behind, speeding up the slot transition rate to catch up. The synchronization process is summarized in Algorithm~\ref{alg:node_sync_simplified}.

\begin{algorithm}[H]
\caption{Node sync}
\label{alg:node_sync_simplified}
\small
\begin{algorithmic}[1]
\algrenewcommand\algorithmicrequire{\textbf{Input:}}
\algrenewcommand\algorithmicensure{\textbf{Output:}}
\Require $t_1, t_2, t_3$ (Timestamps from PNF \textit{UL\_node\_sync}), $t_4$ (VNF local receive timestamp)
\Ensure $\mathit{slot\_adjustment}$ (Slot adjustment accumulator), $\mathit{us\_adjustment}$ (Microsecond adjustment accumulator)

\Statex \textbf{Notation:} 
\Statex $\mathit{offset}$ (Instantaneous timing offset), $\mathit{sync\_locked}$ (Synchronization lock state)
\Statex $T_{\mathrm{slot}}$ (Slot duration in \textmu s), $T_{\mathrm{wrap}}$ (Wrap-around period, $10240000$ \textmu s)
\Statex $\text{WrapCorrection}(x, T)$ (Corrects $x$ within $[-T/2, T/2]$)

\Statex \textbf{Phase I: Timing Offset Calculation}
\State $d_1 \gets \text{WrapCorrection}(t_2 - t_1, T_{\mathrm{wrap}})$
\State $d_2 \gets \text{WrapCorrection}(t_4 - t_3, T_{\mathrm{wrap}})$
\State $\mathit{offset} \gets (d_1 - d_2) / 2$

\Statex \textbf{Phase II: Hysteresis Lock and Clock Adjustment}
\If{$\mathit{sync\_locked} = 1 \land |\mathit{offset}| > T_{\mathrm{slot}}$}
    \State $\mathit{sync\_locked} \gets 0$ \Comment{Unlock due to excessive clock drift}
\EndIf

\If{$\mathit{sync\_locked} = 0$}
    \If{$|\mathit{offset}| \le T_{\mathrm{slot}}$}
        \State $\mathit{sync\_locked} \gets 1$ \Comment{Lock synchronization}
    \Else
        \State $S_{\mathrm{adj}} \gets \mathit{offset} / T_{\mathrm{slot}}$ \Comment{Integer division}
        \State $\mu s_{\mathrm{adj}} \gets \mathit{offset} \pmod{T_{\mathrm{slot}}}$
        \State $\mathit{slot\_adjustment} \gets \mathit{slot\_adjustment} + S_{\mathrm{adj}}$
        \State $\mathit{us\_adjustment} \gets \mathit{us\_adjustment} - \mu s_{\mathrm{adj}}$
    \EndIf
\EndIf
\State \Return $\mathit{slot\_adjustment}, \mathit{us\_adjustment}$
\end{algorithmic}
\end{algorithm}

\section{Delay Management}
\label{subsec:delay_management}

To counteract changing network latency and maintain scheduling stability, a dynamic delay management strategy is implemented. This strategy operates as a closed-loop feedback mechanism based on standard Small Cell Forum (SCF) PNF Timing Info reported by the PNF. By evaluating the Timing Info relative to the PNF deadline, the algorithm dynamically adjusts the scheduling lead time $S_{\mathrm{ahead}}$.

\subsection{Timing Model}
\label{subsec:timing_model}
To formalize the delay management problem, this section introduces the mathematical timing model of the nFAPI-based Split Option 6 architecture. Let $T_{\mathrm{slot}}$ denote the slot duration and $S_{\mathrm{ahead}}$ denote the number of slots by which the VNF scheduler triggers earlier than the target slot. For a scheduling message generated at VNF time $t_g$, the corresponding target PNF processing deadline is determined by the target slot boundary. The Timing Info reported by the PNF is denoted by $\mathit{TimingInfo}[i]$, where $\mathit{TimingInfo}[i] < 0$ indicates that the message arrives before the deadline (early arrival), and $\mathit{TimingInfo}[i] > 0$ indicates a late arrival. Therefore, the delay management objective is to select the minimum stable $S_{\mathrm{ahead}}$ such that late arrivals are avoided ($\mathit{TimingInfo}[i] \le 0$) while the MAC HARQ Round-Trip Time (RTT) is not unnecessarily inflated.


\subsection{EWMA-based Timing Info Estimation}
\label{subsubsec:ewma_estimation}
To smooth high-frequency network noise while remaining sensitive to timing drift, an Exponentially Weighted Moving Average (EWMA) filter is used to estimate the mean late arrival $\mathit{TimingInfoEWMA}[i]$ and the arrival jitter deviation $\mathit{TimingInfoDev}[i]$ based on the observed PNF Timing Info $\mathit{TimingInfo}[i]$ at slot $i$. The mean estimation is updated as:
\begin{equation}
\mathit{TimingInfoEWMA}[i] = (1 - \alpha) \mathit{TimingInfoEWMA}[i-1] + \alpha \mathit{TimingInfo}[i]
\end{equation}
where the smoothing factor is chosen as $\alpha = 1/8$ to track the long-term trend, and the initial value is set to the first observed Timing Info value.

The jitter deviation $\mathit{TimingInfoDev}[i]$ is updated to capture timing variation as:
\begin{equation}
\mathit{TimingInfoDev}[i] = (1 - \beta) \mathit{TimingInfoDev}[i-1] + \beta |\mathit{TimingInfo}[i] - \mathit{TimingInfoEWMA}[i]|
\end{equation}
where $\beta = 1/4$ is the deviation smoothing factor, and its initial value is set to half of the absolute first observed Timing Info value. These parameters are chosen as negative powers of two ($\alpha = 2^{-3}$, $\beta = 2^{-2}$) to allow the algorithm to perform fast bitwise shift operations in real time.

\subsection{Adaptive Slots Ahead Control}
\label{subsubsec:delay_control}
The slots ahead trigger timing $S_{\mathrm{ahead}}$ is dynamically updated using a fast-increase and conservative-decrease control law. Adjustments are gated by a pacing check to ensure decisions are only made when new reports are available. Let $E_i$ be the elapsed slots since the last adjustment, and $P_{\mathrm{slots}} = \max(1, \mathit{Period}_{\mathrm{subframes}} \times 2^\mu)$ be the reporting period in slots. The adjustment logic is executed only if $E_i \ge P_{\mathrm{slots}}$.

The decision rules are defined as follows:
\begin{itemize}
    \item \textbf{Rapid Increase (Preserve Throughput):} If the latest sample is late ($\mathit{TimingInfo}[i] > 0$) or the smoothed worst-case arrival estimate crosses the deadline ($\mathit{TimingInfoEWMA}[i] + \mathit{TimingInfoDev}[i] > 0$), the slots ahead value is immediately increased to prevent late packet arrivals and slot dropouts:
          \begin{equation}
          S_{\mathrm{target}, i+1} = S_{\mathrm{ahead}, i} + \left\lceil \frac{\mathit{TimingInfoEWMA}[i] + \mathit{TimingInfoDev}[i]}{T_{\mathrm{slot}}} \right\rceil
          \end{equation}
    \item \textbf{Gradual Decrease (Optimize Latency):} If the estimated latency shows a safe margin such that the mean arrival time is early enough to absorb both the slot shift and a safety margin of four times the jitter deviation, i.e., $\mathit{TimingInfoEWMA}[i] < -(T_{\mathrm{slot}} + 4 \times \mathit{TimingInfoDev}[i])$, the trigger timing is decremented by one slot to optimize latency:
          \begin{equation}
          S_{\mathrm{target}, i+1} = S_{\mathrm{ahead}, i} - 1
          \end{equation}
    \item \textbf{Maintain Baseline:} Otherwise, the target remains unchanged ($S_{\mathrm{target}, i+1} = S_{\mathrm{ahead}, i}$).
\end{itemize}
The target slots ahead value is then clamped to the range $[S_{\min}, S_{\max}]$:
\begin{equation}
S_{\mathrm{ahead}, i+1} = \max\left(S_{\min}, \min\left(S_{\mathrm{target}, i+1}, S_{\max}\right)\right)
\end{equation}
where $S_{\min} = 3$ and $S_{\max} = \min(8, \lfloor T_{\mathrm{window}} / T_{\mathrm{slot}} \rfloor - 1)$.

Finally, when the reference frame shifts due to a slots ahead adjustment ($\delta = S_{\mathrm{ahead}, i+1} - S_{\mathrm{ahead}, i} \neq 0$), the Timing Info history is compensated to align the EWMA state with the new scheduling baseline and prevent transient control loop oscillations:
\begin{equation}
\mathit{TimingInfoEWMA}[i] \gets \mathit{TimingInfoEWMA}[i] - \delta \times T_{\mathrm{slot}}
\end{equation}

The core delay management strategy is condensed in Algorithm~\ref{alg:delay_management}.

\begin{algorithm}[!htbp]
\caption{Delay Management}
\label{alg:delay_management}
\footnotesize
\begin{algorithmic}[1]
\algrenewcommand\algorithmicrequire{\textbf{Input:}}
\algrenewcommand\algorithmicensure{\textbf{Output:}}
\Require $\mathit{TimingInfo}[i]$ (Observed PNF Timing Info), $S_{\mathrm{curr}}$ (Current trigger timing), $T_{\mathrm{window}}$ (Timing window), $T_{\mathrm{slot}}$ (Slot duration)
\Ensure $S_{\mathrm{next}}$ (Trigger timing for the next MAC schedule)
\Statex 
\Statex \textbf{Notation:} 
\Statex $\mathit{TimingInfoEWMA}[i]$ (smoothed mean PNF Timing Info), $\mathit{TimingInfoDev}[i]$ (smoothed arrival jitter)
\Statex $S_{\max}, S_{\min}$ (Boundary limits)
\Statex $\alpha, \beta$ (Smoothing factors for latency and jitter)
\Statex $E$ (Elapsed slots since last adjustment), $P_{\mathrm{slots}}$ (Pacing period in slots)
 
\Statex \textbf{Phase I: Latency and Jitter Estimation}
\State $\mathit{TimingInfoEWMA}[i] \gets (1 - \alpha)\mathit{TimingInfoEWMA}[i-1] + \alpha \mathit{TimingInfo}[i]$ \Comment{Update mean PNF Timing Info}
\State $\mathit{TimingInfoDev}[i] \gets (1 - \beta)\mathit{TimingInfoDev}[i-1] + \beta |\mathit{TimingInfo}[i] - \mathit{TimingInfoEWMA}[i]|$ \Comment{Update arrival jitter}

\Statex \textbf{Phase II: Pacing Gate and Adjustment Decision}
\If{$E < P_{\mathrm{slots}}$}
    \State \Return $S_{\mathrm{curr}}$ \Comment{Gated: defer decision}
\EndIf
\State $S_{\mathrm{target}} \gets S_{\mathrm{curr}}$
\If{$\mathit{TimingInfo}[i] > 0$ \textbf{or} $(\mathit{TimingInfoEWMA}[i] + \mathit{TimingInfoDev}[i]) > 0$}
    \State $\Delta \gets \left\lceil (\mathit{TimingInfoEWMA}[i] + \mathit{TimingInfoDev}[i]) / T_{\mathrm{slot}} \right\rceil$
    \If{$\Delta > 0$}
        \State $S_{\mathrm{target}} \gets S_{\mathrm{curr}} + \Delta$ \Comment{Rapid Increase}
    \EndIf
\ElsIf{$\mathit{TimingInfoEWMA}[i] < -(T_{\mathrm{slot}} + 4 \times \mathit{TimingInfoDev}[i])$}
    \State $S_{\mathrm{target}} \gets S_{\mathrm{curr}} - 1$ \Comment{Gradual Decrease}
\EndIf
\State $S_{\mathrm{next}} \gets \max(S_{\min}, \min(S_{\mathrm{target}}, S_{\max}))$ \Comment{Clamp to $[3, S_{\max}]$}
\If{$S_{\mathrm{next}} \neq S_{\mathrm{curr}}$}
    \State $\delta \gets S_{\mathrm{next}} - S_{\mathrm{curr}}$
    \State $\mathit{TimingInfoEWMA}[i] \gets \mathit{TimingInfoEWMA}[i] - \delta \times T_{\mathrm{slot}}$ \Comment{Compensate reference frame shift}
    \State Update last adjustment time reference
\EndIf
\State \Return $S_{\mathrm{next}}$
\end{algorithmic}
\end{algorithm}


\subsection{Coordination between Node Sync and Delay Management}
\label{subsec:coordination}

To ensure stable operation under real-world conditions, node sync and delay management must coordinate without inducing control loop oscillations. The microsecond-level node sync focuses strictly on correcting clock phase offsets to align the VNF's scheduling thread with the PNF's slot transitions. Because it directly shifts the VNF's time base, any clock adjustment ($S_{adj}, \mu s_{adj}$) temporarily shifts the arrival timestamp reference. Delay management is designed to absorb this transient shifting. By relying on history-weighted EWMA-based risk tracking ($R_i$), delay management avoids reacting to the temporary timing offsets caused by clock adjustments, allowing node sync to converge. Once node sync locks synchronization ($\mathit{sync\_locked} = 1$), the time base stabilizes, allowing delay management to achieve precise slot-level optimizations ($S_{\mathrm{ahead}}$).
