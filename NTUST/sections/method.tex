\chapter{Proposed Method}
\label{sec:method}

This chapter details the proposed dynamic timing adjustment framework. To address the unstable transmission latency during packet transmission between the PNF and VNF, we propose two core timing control algorithms: node sync for software-level clock synchronization and delay management for slot-level adaptive delay management. The timing control of this system is organized as a closed-loop system, ensuring that the VNF-side scheduling can dynamically track and compensate for both microsecond-level clock drift and slot-level transport latency variation. The two core algorithms cooperate as follows:

\begin{enumerate}
    \item \textbf{Node sync:} Maintains phase and slot boundary alignment between the VNF and PNF. It periodically exchanges timestamps to calculate the absolute phase offset, correcting for hardware clock drift (Clock Drift).
    \item \textbf{Delay Management:} Tracks and estimates packet transport delays and jitter at the slot level, dynamically adjusting the slots ahead ($S_{\mathrm{ahead}}$) to guarantee that control messages fall within the PNF's strict timing window.
\end{enumerate}

\section{Node sync}
\label{subsec:node_sync}
To achieve software-level clock synchronization, the system implements a latency probe procedure compliant with the nFAPI specification. In this procedure, the VNF periodically transmits a downlink node synchronization (DL Node Sync) message containing a parameter $t_1$, which represents the transmission time offset in microseconds relative to the VNF SFN/slot 0/0 time reference. Upon receiving this message at the transport layer, the PNF records $t_2$, representing the arrival time offset in microseconds relative to the PNF SFN/slot 0/0 time reference. The PNF then immediately responds by sending an uplink node synchronization (UL Node Sync) message back to the VNF, indicating the echoed $t_1$, the recorded arrival offset $t_2$, and a parameter $t_3$ representing the transmission offset of the uplink message relative to the PNF SFN/slot 0/0 time reference. When the VNF receives the UL Node Sync message, it records a local arrival timestamp $t_4$, representing the arrival time offset in microseconds relative to the VNF SFN/slot 0/0 time reference.

Because the nFAPI timestamps are constrained by a 1024 subframe number (SFN) loop, offsets wrap around every 10.24 seconds (10,240,000 $\mu$s). The algorithm calculates the differences $d_1 = t_2 - t_1$ and $d_2 = t_4 - t_3$, applying a wrap-around correction to align them within the interval $[-5,120,000, 5,120,000]$ $\mu$s. The VNF then calculates the instantaneous clock offset between their respective time references:
\begin{equation}
\mathit{offset} = \frac{d_1 - d_2}{2}
\end{equation}
To prevent timing adjustments from causing control loop oscillations, the synchronization control loop implements a state-based locking mechanism. The system has two synchronization states: locked ($\mathit{sync\_locked} = 1$) and unlocked ($\mathit{sync\_locked} = 0$). In the locked state, the VNF monitors the drift of the local clock. If the absolute offset exceeds the slot duration $T_{\mathrm{slot}}$:
\begin{equation}
|\mathit{offset}| > T_{\mathrm{slot}}
\end{equation}
the VNF unlocks the synchronization ($\mathit{sync\_locked} = 0$) to trigger re-synchronization. In the unlocked state, the VNF checks whether the offset has converged within the slot duration $T_{\mathrm{slot}}$. If $|\mathit{offset}| \le T_{\mathrm{slot}}$, the system locks the synchronization state ($\mathit{sync\_locked} = 1$). Otherwise, the VNF decomposes the offset into a slot-level adjustment $S_{\mathrm{adj}}$ and a microsecond-level adjustment $\mu s_{\mathrm{adj}}$ based on the slot duration $T_{\mathrm{slot}}$:
\begin{equation}
S_{\mathrm{adj}} = \mathit{offset} / T_{\mathrm{slot}}
\end{equation}
\begin{equation}
\mu s_{\mathrm{adj}} = \mathit{offset} \pmod{T_{\mathrm{slot}}}
\end{equation}
These adjustments are accumulated into the global adjustment variables:
\begin{equation}
\mathit{slot\_adjustment} \gets \mathit{slot\_adjustment} + S_{\mathrm{adj}}
\end{equation}
\begin{equation}
\mathit{us\_adjustment} \gets \mathit{us\_adjustment} - \mu s_{\mathrm{adj}}
\end{equation}
The negative sign in the microsecond adjustment reduces the local thread sleep time when the VNF clock is behind, speeding up the slot transition rate to catch up. The synchronization process is summarized in Algorithm~\ref{alg:node_sync_simplified}.

\begin{algorithm}[H]
\caption{Node sync}
\label{alg:node_sync_simplified}
\small
\begin{algorithmic}[1]
\algrenewcommand\algorithmicrequire{\textbf{Input:}}
\algrenewcommand\algorithmicensure{\textbf{Output:}}
\Require $t_1, t_2, t_3$ (Timestamps from PNF \textit{UL\_node\_sync}), $t_4$ (VNF local receive timestamp)
\Ensure $\mathit{slot\_adjustment}$ (Slot adjustment accumulator), $\mathit{us\_adjustment}$ (Microsecond adjustment accumulator)

\Statex \textbf{Notation:} 
\Statex $\mathit{offset}$ (Instantaneous timing offset), $\mathit{sync\_locked}$ (Synchronization lock state)
\Statex $T_{\mathrm{slot}}$ (Slot duration in~$\mu$s), $T_{\mathrm{wrap}}$ (Wrap-around period, $10240000$~$\mu$s)
\Statex $\text{WrapCorrection}(x, T)$ (Corrects $x$ within $[-T/2, T/2]$)

\Statex \textbf{Phase I: Timing Offset Calculation}
\State $d_1 \gets \text{WrapCorrection}(t_2 - t_1, T_{\mathrm{wrap}})$
\State $d_2 \gets \text{WrapCorrection}(t_4 - t_3, T_{\mathrm{wrap}})$
\State $\mathit{offset} \gets (d_1 - d_2) / 2$

\Statex \textbf{Phase II: Hysteresis Lock and Clock Adjustment}
\If{$\mathit{sync\_locked} = 1 \land |\mathit{offset}| > T_{\mathrm{slot}}$}
    \State $\mathit{sync\_locked} \gets 0$ \Comment{Unlock due to excessive clock drift}
\EndIf

\If{$\mathit{sync\_locked} = 0$}
    \If{$|\mathit{offset}| \le T_{\mathrm{slot}}$}
        \State $\mathit{sync\_locked} \gets 1$ \Comment{Lock synchronization}
    \Else
        \State $S_{\mathrm{adj}} \gets \mathit{offset} / T_{\mathrm{slot}}$ \Comment{Integer division}
        \State $\mu s_{\mathrm{adj}} \gets \mathit{offset} \pmod{T_{\mathrm{slot}}}$
        \State $\mathit{slot\_adjustment} \gets \mathit{slot\_adjustment} + S_{\mathrm{adj}}$
        \State $\mathit{us\_adjustment} \gets \mathit{us\_adjustment} - \mu s_{\mathrm{adj}}$
    \EndIf
\EndIf
\State \Return $\mathit{slot\_adjustment}, \mathit{us\_adjustment}$
\end{algorithmic}
\end{algorithm}

\section{Delay Management}
\label{subsec:delay_management}

To counteract changing network latency and maintain scheduling stability, a dynamic delay management strategy is implemented. This strategy operates as a closed-loop feedback mechanism based on standard Small Cell Forum (SCF) PNF Timing Info reported by the PNF. By evaluating the Timing Info relative to the PNF deadline, the algorithm dynamically adjusts the scheduling ahead time $S_{\mathrm{ahead}}$.


To formalize the delay management problem, this section introduces the mathematical timing model of the nFAPI-based Split Option 6 architecture. Let $T_{\mathrm{slot}}$ denote the slot duration and $S_{\mathrm{ahead}}$ denote the number of slots by which the VNF scheduler triggers earlier than the target slot. For a scheduling message generated at VNF time $t_g$, the corresponding target PNF processing deadline is determined by the target slot boundary. The Timing Info reported by the PNF is denoted by $\mathit{TimingInfo}[i]$, where $\mathit{TimingInfo}[i] < 0$ indicates that the message arrives before the deadline (early arrival), and $\mathit{TimingInfo}[i] > 0$ indicates a late arrival. Therefore, the delay management objective is to select the minimum stable $S_{\mathrm{ahead}}$ such that late arrivals are avoided ($\mathit{TimingInfo}[i] \le 0$) while the MAC HARQ Round-Trip Time (RTT) is not unnecessarily inflated.


\subsection{EWMA-based Timing Info Estimation}
\label{subsubsec:ewma_estimation}
When functional splits are deployed over packet-switched networks, the jitter of packet latency varies a lot with the network load. To address this, the proposed method references the congestion avoidance and control algorithm proposed by Jacobson and Karels~\cite{jacobson1988congestion} to introduce an Exponentially Weighted Moving Average (EWMA) filter that tracks both the mean and the deviation of the timing info. This filter smooths sudden network jitter, and its weight parameters can be changed into bitwise shift operations to reduce the computing overhead in the RAN underlayer~\cite{jacobson1988congestion}. Specifically, an EWMA filter is used to estimate the mean late arrival $\mathit{TimingInfoEWMA}[i]$ and the arrival jitter deviation $\mathit{TimingInfoDev}[i]$ based on the observed PNF Timing Info $\mathit{TimingInfo}[i]$ at slot $i$. The mean estimation is updated as:
\begin{equation}
\begin{split}
\mathit{TimingInfoEWMA}[i] & = (1 - \alpha) \mathit{TimingInfoEWMA}[i-1] \\
& \quad + \alpha \mathit{TimingInfo}[i]
\end{split}
\end{equation}
where the smoothing factor is chosen as $\alpha = 1/8$ to track the long-term trend, and the initial value is set to the first observed Timing Info value.

The jitter deviation $\mathit{TimingInfoDev}[i]$ is updated to capture timing variation as:
\begin{equation}
\begin{split}
\mathit{TimingInfoDev}[i] & = (1 - \beta) \mathit{TimingInfoDev}[i-1] \\
& \quad + \beta |\mathit{TimingInfo}[i] - \mathit{TimingInfoEWMA}[i]|
\end{split}
\end{equation}
where $\beta = 1/4$ is the deviation smoothing factor, and its initial value is set to half of the absolute first observed Timing Info value. To design the decision thresholds for the slots ahead, we use the network latency estimation parameters defined in the IETF RFC 6298 standard~\cite{rfc6298}. Specifically, we set the mean gain to $\alpha = 1/8$ and the deviation gain to $\beta = 1/4$, and use four times the deviation as a safety margin~\cite{rfc6298}. This parameter combination is a standard that has been tested in the industry for a long time. It covers most extreme network delays in a safe and stable way, ensuring that the nFAPI Split 6 architecture keeps strict timing synchronization and system stability under unpredictable jitter. These parameters are chosen as negative powers of two ($\alpha = 2^{-3}$, $\beta = 2^{-2}$) to allow the algorithm to perform fast bitwise shift operations in real time.

\subsection{Adaptive Slots Ahead Control}
\label{subsubsec:delay_control}
The slots ahead trigger timing $S_{\mathrm{ahead}}$ is dynamically updated using a fast-increase and conservative-decrease control law. The adjustment logic is executed upon receiving each Timing Info report.

The decision rules are defined as follows:
\begin{itemize}
    \item \textbf{Rapid Increase (Preserve Throughput):} If the smoothed worst-case arrival estimate (representing timing risk $\mathit{TimingInfoEWMA}[i]$ $+$ $\mathit{TimingInfoDev}[i]$) crosses the deadline ($\mathit{TimingInfoEWMA}[i]$ $+$ $\mathit{TimingInfoDev}[i] > 0$), the slots ahead value is immediately increased to prevent late packet arrivals and slot dropouts:
          \begin{equation}
          S_{\mathrm{next}} = S_{\mathrm{curr}} + \left\lceil \frac{\mathit{TimingInfoEWMA}[i] + \mathit{TimingInfoDev}[i]}{T_{\mathrm{slot}}} \right\rceil
          \end{equation}
    \item \textbf{Gradual Decrease (Reduce Latency):} If estimated latency shows a safe margin (worst-case arrival is early enough), i.e., when the sum $\mathit{TimingInfoEWMA}[i] + 4 \times \mathit{TimingInfoDev}[i] < -T_{\mathrm{slot}}$, the trigger timing is decremented by one slot to reduce latency:
          \begin{equation}
          S_{\mathrm{next}} = S_{\mathrm{curr}} - 1
          \end{equation}
    \item \textbf{Maintain Baseline:} Otherwise, the trigger timing remains the same:
          \begin{equation}
          S_{\mathrm{next}} = S_{\mathrm{curr}}
          \end{equation}
\end{itemize}
To ensure the trigger timing remains within valid operational boundaries, the adjusted value is clamped to the range $[1, \lfloor T_{\mathrm{window}} / T_{\mathrm{slot}} \rfloor]$:
\begin{equation}
S_{\mathrm{next}} \gets \max\left(1, \min\left(S_{\mathrm{next}}, \left\lfloor \frac{T_{\mathrm{window}}}{T_{\mathrm{slot}}} \right\rfloor \right)\right)
\end{equation}
where the trigger timing is bounded by 1 and the maximum number of slots in the timing window $\lfloor T_{\mathrm{window}} / T_{\mathrm{slot}} \rfloor$.

The core delay management strategy is condensed in Algorithm~\ref{alg:delay_management}.

\begin{algorithm}[!htbp]
\caption{Delay Management}
\label{alg:delay_management}
\small
\begin{algorithmic}[1]
\algrenewcommand\algorithmicrequire{\textbf{Input:}}
\algrenewcommand\algorithmicensure{\textbf{Output:}}
\Require $\mathit{TimingInfo}[i]$ (Observed PNF Timing Info), 
\Statex \hskip\algorithmicindent $S_{\mathrm{curr}}$ (Current trigger timing), 
\Statex \hskip\algorithmicindent $T_{\mathrm{window}}$ (Timing window), $T_{\mathrm{slot}}$ (Slot duration)
\Ensure $S_{\mathrm{next}}$ (Trigger timing for the next MAC schedule)
\Statex 
\Statex \textbf{Notation:} 
\Statex $\mathit{TimingInfoEWMA}[i]$, $\mathit{TimingInfoDev}[i]$: 
\Statex \hskip\algorithmicindent smoothed mean and arrival jitter
\Statex $\alpha, \beta$: smoothing factors
 
\Statex \textbf{Phase I: Latency and Jitter Estimation}
\State $\mathit{TimingInfoEWMA}[i] \gets (1 - \alpha)\mathit{TimingInfoEWMA}[i-1]$ 
\Statex \hskip\algorithmicindent $+ \alpha \mathit{TimingInfo}[i]$
\State $\mathit{TimingInfoDev}[i] \gets (1 - \beta)\mathit{TimingInfoDev}[i-1] + {}$
\Statex \hskip\algorithmicindent $\beta |\mathit{TimingInfo}[i] - \mathit{TimingInfoEWMA}[i]|$

\Statex \textbf{Phase II: Adjustment Decision}
\If{$\mathit{TimingInfoEWMA}[i] + \mathit{TimingInfoDev}[i] > 0$}
    \State $S_{\mathrm{next}} \gets S_{\mathrm{curr}} + {}$
    \Statex \hskip 2.5em $\left\lceil \frac{\mathit{TimingInfoEWMA}[i] + \mathit{TimingInfoDev}[i]}{T_{\mathrm{slot}}} \right\rceil$ \Comment{Rapid Increase}
\ElsIf{$\mathit{TimingInfoEWMA}[i] + 4 \times \mathit{TimingInfoDev}[i] < -T_{\mathrm{slot}}$}
    \State $S_{\mathrm{next}} \gets S_{\mathrm{curr}} - 1$ \Comment{Gradual Decrease}
\Else
    \State $S_{\mathrm{next}} \gets S_{\mathrm{curr}}$ \Comment{Maintain Baseline}
\EndIf
\State $S_{\mathrm{next}} \gets \max\left(1, \min\left(S_{\mathrm{next}}, \left\lfloor \frac{T_{\mathrm{window}}}{T_{\mathrm{slot}}} \right\rfloor\right)\right)$ \Comment{Clamp boundaries}
\State \Return $S_{\mathrm{next}}$
\end{algorithmic}
\end{algorithm}




To ensure stable operation under real-world conditions, node sync and delay management must coordinate without inducing control loop oscillations. The microsecond-level node sync focuses strictly on correcting clock phase offsets to align the VNF's scheduling thread with the PNF's slot transitions. Because it directly shifts the VNF's time base, any clock adjustment ($S_{adj}, \mu s_{adj}$) temporarily shifts the arrival timestamp reference. Delay management is designed to absorb this transient shifting. By relying on history-weighted EWMA-based risk tracking ($\mathit{TimingInfoEWMA}[i]$ $+$ $\mathit{TimingInfoDev}[i]$), delay management avoids reacting to the temporary timing offsets caused by clock adjustments, allowing node sync to converge. Once node sync locks synchronization ($\mathit{sync\_locked} = 1$), the time base stabilizes, allowing delay management to achieve precise slot-level optimizations ($S_{\mathrm{ahead}}$).
